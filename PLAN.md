# auto-punk — Implementation Plan

A browser-based tabletop RPG platform with an **AI game master** and a mix of **AI + human players**. No accounts: rooms are addressed by an autogenerated unique instance id, and players join via a shared link plus a name. v1 ships **Cyberpunk 2020**, driven by a local **LM Studio** LLM (`qwen3.8-27b` at `localhost:1234`).

## Goals / non-goals
- **Goal:** host creates a room → shares link → players (human + AI) join, build characters, and the AI GM runs structured rounds with full state + action-log tracking. Resumable across refresh/restart.
- **Non-goal (v1):** multiple RPG systems beyond Cyberpunk 2020 (architecture is game-pluggable), accounts/auth, cloud hosting, mobile-native.

## Confirmed decisions
| Decision | Choice |
|---|---|
| Deployment | Single Node.js server co-located with LM Studio; players join over the network via link |
| Rules depth | Core Cyberpunk 2020 mechanics first (attributes/skills/Edge Pool/d10 rolls/basic combat) |
| Turn model | Structured rounds: collect all actions → GM resolves together → narrate |
| Character creation | Guided form for humans; LLM-generated sheets for AI players from a persona |
| Persistence | Resumable/persisted (character states + full action log to disk) |
| Model | Fixed `qwen3.8-27b` via LM Studio OpenAI-compatible API |

## Architecture
```
Browser players ──(HTTP + WebSocket link)──▶ Node.js Server  ──(localhost:1234, fetch)──▶ LM Studio (qwen3.8-27b)
   React + Vite + Zustand                      │ authoritative state · rules engine · LLM orchestration
                                               └────────▶ JSON file store (rooms/players/characters/events)
```
The **server is the single source of truth**: it owns game state, runs the rules engine, sequences structured rounds as transactions, and makes all LLM calls. Browsers are thin clients that render state and submit actions over WebSocket.

## Tech stack
| Layer | Choice | Notes |
|---|---|---|
| Monorepo | npm workspaces | pnpm not installed; share one TS codebase |
| Shared logic | `packages/shared` (pure TS, no deps) | Rules engine + types used by both sides; unit-testable |
| Server | Node 26 + **Fastify** + **ws** + built-in `fetch`/`crypto`/`fs` | Minimal deps; LLM via raw fetch to OpenAI-compatible endpoint (no SDK); WebSocket via `ws` |
| Persistence | Write-through **JSON file store** behind a `Store` interface | Zero native deps on Node 26; SQLite is a drop-in upgrade later |
| Client | React + Vite + TypeScript + Zustand + `ws` client | Real-time UI state |

## Data model & persistence
Write-through JSON store (atomic writes), hydrated into an in-memory room cache on boot:
- **rooms** — `id` (nanoid = the "unique instance id"), `gameId` (`cyberpunk2020`), `status`, `worldSummary`, timestamps.
- **players** — `roomId`, `seatToken` (client-generated, stored in localStorage → survives refresh/rejoin with no account), `name`, `kind: human|ai`, `isHost`.
- **characters** — full Cyberpunk 2020 sheet + current state; AI chars also carry `persona`, `goals`, `secrets` that drive the LLM.
- **events** — append-only log of every action, dice roll, narration, and state change (`roomId`, `seq`, `type`, `payload`). Powers the UI feed, resumability, and context compaction.

Rejoin: link = `/r/<roomId>` → enter name → server binds/reuses the localStorage seat token to a player seat. On boot the server hydrates active rooms from disk.

## Cyberpunk 2020 rules engine (`packages/shared`, behind a `GameSystem` interface)
- **Attributes:** Body, Cool, Intelligence, Reflexes, Tech, Empathy.
- **Derived stats:** HP = Body + 5; Soak = floor(Body/2); Move from Reflexes.
- **Skills** grouped by category with ratings (0–5+).
- **Edge Pool** (spendable bonus dice).
- **d10 pool rolls:** roll `pool` d10s, count 5+ as successes, fumble on any 1; opposed-roll resolution. Dice are rolled by the deterministic engine (seeded RNG), never invented by the LLM — results feed into prompts so the model narrates but doesn't decide outcomes.
- **Combat sub-state:** initiative ordered by Reflexes, damage vs Soak/HP.

> Exact success/fumble thresholds and opposed-roll tiebreaks are confirmed against the chosen CP2020 rulebook during P2 (edition variants exist).

## LLM orchestration (`GameDirector` service on server)
Four prompt templates; structured JSON requested where machine-readable output is needed:
1. **AI character sheet generation** — persona → valid Cyberpunk sheet (validated against the rules engine; retry/repair on bad JSON).
2. **AI player action decision** — per AI, given scene + char/persona + recent log → `{intent, target, skillUsed, dicePool}`.
3. **GM narration + resolution** — given world state, all declared actions this round, and engine roll results → `{narration, stateChanges[]}`.
4. **Log compaction** — every K events (or when context grows), summarize old log into a rolling `worldSummary`.

Context management: each call gets a bounded prompt = system rules + `worldSummary` + current `stateSnapshot` (all chars' stats) + last N raw events + the task, keeping prompts inside the model's window across long sessions. AI action decisions are parallelized; GM narration is streamed to the UI to hide latency.

## Game loop / state machine (server-authoritative, structured rounds)
`CREATING → CHARACTER_CREATION → READY_CHECK → PLAYING ⇄ COMBAT → ENDED`

A round is a transaction:
1. GM presents/advances the scene (LLM).
2. Collect actions — humans submit via UI; each AI auto-decides (parallel LLM calls). Server waits until all human players are ready or host forces proceed.
3. Engine rolls dice for any skill tests/combat.
4. GM resolves + narrates (LLM); apply `stateChanges` to characters.
5. Commit state + append events → broadcast via WebSocket. If combat triggered, enter initiative sub-loop.

## Frontend screens
- **Landing:** create room / join by link.
- **Join:** enter name (seat token auto-generated).
- **Lobby:** player list, game picker (Cyberpunk 2020), AI-player config (count + personas/roles), character creation forms, ready status, host "Start."
- **Game view:** scrolling narration/event feed, per-character sheet panels (HP/Soak/Edge bars), action input box for the human, dice-roll results, combat tracker (initiative order).

## Milestones
- **P0 — Scaffold:** monorepo, shared types, dev tooling, JSON store + repository.
- **P1 — Rooms & presence:** create/join via link, lobby, WebSocket presence, seat tokens, room/player persistence.
- **P2 — Characters:** rules engine (shared) + human guided forms + AI sheet generation; ready-check → start. *(Confirm CP2020 dice thresholds here.)*
- **P3 — Core loop:** structured rounds, action collection, dice rolls, GM narration via LM Studio, event feed UI, state updates.
- **P4 — Autonomy & combat:** per-AI decision calls, initiative sub-state, Edge Pool spending.
- **P5 — Hardening:** context compaction, resumability polish, LLM-downtime handling (queue/retry + status), tests.

## Testing
- **Unit** (high value): pure rules engine — dice rolls, success/fumble counting, HP/Soak math, opposed rolls. Deterministic.
- **Integration:** scripted round against a mock LLM client (canned JSON) to validate state transitions + persistence without hitting the real model.
- **Manual:** live playtest against LM Studio.

## Risks / mitigations
1. Structured-output reliability of `qwen3.8-27b` → JSON schema + validation + retry/repair parsing.
2. Context window limits on long sessions → compaction strategy (P5).
3. Round latency from N sequential LLM calls → parallelize AI decisions, stream GM output.
4. CP2020 rulebook variant → pin exact dice rules in P2.

## Defaults
1–5 AI players per room (configurable), up to ~8 total seats, English play (multi-language is a later prompt change).
